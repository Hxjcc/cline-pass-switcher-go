# 转发性能与回放资源边界

本轮调整针对长流的内存分配和请求路径的元数据读取，不改变账号选择、渠道切换或工具协议语义。

## 实现

- 思考文本、正文和工具参数使用可增长缓冲累加，实时 delta 照常发送，最终内容仍完整返回。
- 请求路径通过 `Store.ModelMeta`、`ModelConfig`、`ProxyKey`、`UpstreamBase` 读取所需数据。模型快照的 map、slice、指针单独复制，调用方不能修改存储；管理接口需要全量目录时仍可使用原有接口。
- Responses 共享流只编码一次带有 sequence_number 的 SSE；所有订阅按独立字节偏移从头读取，不保留每个事件的 Go map 对象，也不建立无限增长的事件索引。
- 回放使用 32 KiB 内存块，按实际块容量计费。单流内存预算 1 MiB，进程内所有共享流合计 32 MiB，超过任一内存预算后将该流完整移到系统临时文件。
- 回放总量按编码后的 SSE 字节计费，单流上限 128 MiB、进程合计 1 GiB。超限或磁盘错误时停止该上游读取，客户端收到 `replay_storage_error`，历史记录失败；不会丢掉旧事件后继续报成功。
- 心跳由各客户端在等待新数据时产生，不进入回放缓存。客户端写入与 flush 最多连续阻塞 30 秒，超时释放该订阅，健康订阅继续。
- 上游结束且所有订阅释放后，归还预算并删除临时文件。最后一个订阅离开后的 400 ms 重连宽限保持不变；流结束后的新请求仍重新生成。

这些预算不是进程总内存上限。转换器的完整输出、单次 JSON 编码、每个订阅的读块和网络缓冲仍需内存。临时文件包含实际响应内容；正常结束和取消会清理，进程异常退出可能残留。硬上限在 `internal/httpapi/stream_replay.go` 的 `defaultReplayLimits` 定义。

## 本地微基准

环境：Windows/amd64，Go 1.25.3，AMD Ryzen 7 6800H。同一台机器、同一组 benchmark，`-benchtime=200ms -count=1`；单次短基准数值仅用于观察数量级，不是线上吞吐承诺。

流累加案例：256 KiB 内容、2048 个 128-byte 分片，经过 Chat chunk 状态机并生成 Responses 事件。表中的分配字节是一次操作的累计分配量，不是峰值驻留内存。

| 操作 | 改前时间 | 改后时间 | 改前分配 | 改后分配 |
|---|---:|---:|---:|---:|
| 正文流 | 48.36 ms | 1.62 ms | 278.67 MB | 3.85 MB |
| 思考流 | 35.55 ms | 1.43 ms | 278.35 MB | 3.54 MB |
| 工具参数流 | 38.85 ms | 3.83 ms | 281.34 MB | 6.26 MB |
| 从 1000 个模型的目录读取一个模型 | 4.67 ms | 0.342 µs | 2.34 MB | 768 B |

模型读取案例改前通过整份 metadata 的 JSON 克隆再取值，改后只复制指定模型。生产收益取决于目录大小与并发量。上述耗时不包括真实模型生成、网络和磁盘回放开销。

运行：

```sh
go test ./internal/responses ./internal/store -run '^$' -bench 'Benchmark(StreamAccumulation|RequestModelMetadata)$' -benchmem -benchtime=200ms -count=1
go test ./...
go vet ./...
```

回归覆盖：内存到文件切换、全局与单流预算、存储失败唤醒、并发读写、从零重连与 sequence_number、心跳不积累、取消、旧任务被替换后的清理、慢客户端与健康客户端隔离、超限错误及历史记录、模型快照隔离。
