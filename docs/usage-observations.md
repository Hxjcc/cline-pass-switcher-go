# Cline Pass 用量实测

2026-10-31（Asia/Shanghai），使用本地 `a4f58f7`、独立测试数据目录和 Cline 原生上游，对 `cline-pass/deepseek-v4.1-flash-1017` 发起 8 次真实模型请求。上游报告的累计实际费用为 0.044932896 美元。下面是本次样本的观测，不代表所有模型或后续上游版本都返回相同元数据。

## 上游实际返回了什么

| 请求 | 内部模型轮数 | 上游累计输入 | 返回客户端的输入 | 来源 |
|---|---:|---:|---:|---|
| 普通请求 | 1 | 49 | 49 | 单轮原始值 |
| 一次搜索，非流式 | 2 | 7,784 | 3,892 | 平均估算 |
| 两次顺序搜索，流式 | 3 | 15,285 | 5,095 | 平均估算 |
| 真实 Codex，两次顺序搜索 | 3 | 21,004 | 7,001 | 平均估算 |
| 真实 Codex，长历史后两次顺序搜索 | 3 | 282,029 | 94,009 | 平均估算 |

这些多轮响应中的 `providerAttempts` 包含 `toolLoopLegIndex`，但没有每轮独立的 `usage`。流式响应也只有末尾一次累计 usage，不能通过相邻 usage 相减恢复最后一轮输入。当前“优先独立最后一轮 usage”的分支没有在这些样本中触发；不能把平均数称为实测最后一轮输入。

长历史样本紧接着不搜索的一轮实际输入为 92,683。内部搜索文本不完整保留到下一轮，因此累计输入、上游最后一轮输入和客户端下一轮持有的历史是三种口径。该后续请求还增加了新用户消息，不能把它作为上一轮真实输入的精确基准，也不能据此证明平均估算的固定误差率。

所有真实请求的历史记录仍保留上游累计 token 和实际费用，没有使用折算输入重新计算扣费。

## Codex 是否使用这些数值

真实请求通过桌面附带的 Codex `0.166.0-alpha.5.1` app-server 完成。`thread/tokenUsage/updated` 中的 `last.inputTokens`、`last.totalTokens` 与代理返回值一致；输出 token 同样进入本轮总数。API 的 `context_usage_estimated` 扩展标记不出现在这个事件里，不能假设客户端界面会展示估算提示。

另外，用稳定版 Codex `0.166.0` 离线回放同一份真实响应，将自动压缩阈值设为 10,000，仅替换 usage 数值：

| 回放方式 | 输入 | 输出 | 本轮总数 | 下一轮是否请求压缩 |
|---|---:|---:|---:|---|
| 当前估算值 | 7,001 | 857 | 7,858 | 否 |
| 上游累计值 | 21,004 | 857 | 21,861 | 是 |

压缩请求到达本地测试端点后即被拦截，不调用真实上游。该对照验证提前压缩的触发行为，不测试压缩内容质量，也没有产生额外上游费用。

## 本次采取的修改

- 保留现有平均估算回退，不把累计值直接当成当前上下文，也不把估算标为真实最后一轮值。要取得精确的最后一轮输入，需要上游补充该轮独立 usage。
- 修正文档和代码注释，明确上游输入、客户端历史与累计计费的区别，以及输出 token 对客户端总数的影响。
- 加入脱敏的真实响应样本 `internal/httpapi/testdata/cline-usage-observed.json`，回归检查 JSON、SSE 及缓冲回退路径，验证客户端折算不会改变历史记录、按日统计和客户端密钥扣费。
- 回放发现：上游在流式请求中返回 `{success,data}` 包装的完整 JSON 时，缓冲回退没有解开包装，会误判为 502。统一返回包装内的 completion 后，choices、usage 和路由元数据可以继续转换和记账。

离线回归命令：

```bash
go test ./internal/httpapi -run '^TestObservedClineUsageSeparatesContextFromBilling$' -count=1 -v
```
